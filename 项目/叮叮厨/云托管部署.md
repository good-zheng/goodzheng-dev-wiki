# 叮叮厨 · 云托管部署

部署形态：微信云托管（CloudRun）+ 其内置镜像仓库 `ccr.ccs.tencentyun.com`。每个服务一份 `DEPLOY_CLOUDRUN.md` 台账（`services/api`、`services/chat`、`apps/brand`），记录镜像地址、端口、健康检查与环境变量清单。

## 入口脚本

| 目的 | 命令（仓库根） |
| --- | --- |
| 主后端镜像 | `pnpm api:deploy` |
| 聊天服务镜像 | `pnpm chat:deploy` |
| Redis 镜像 | `pnpm redis:deploy` |
| 介绍站镜像 | `pnpm brand:deploy` |
| 用官方 Docker Hub 基础镜像 | 以上任一加 `:official` 变体（等价 `USE_OFFICIAL_IMAGES=1`） |

脚本统一经 `node scripts/run-sh.mjs` 调用，不要写成 `bash foo.sh`：Windows 上 PATH 里的 `bash.exe` 常解析成 WSL 存根，直接 `execvpe(/bin/bash) failed`。`run-sh.mjs` 显式定位 Git Bash，并支持 `--env KEY=VAL` 传参。

推送前需要手工登录：`docker login ccr.ccs.tencentyun.com --username=<账号 ID>`，密码是控制台「访问凭证」里的固定密码，不是登录密码。`docker push` 返回 0 不代表 tag 落库，脚本末尾用 `docker manifest inspect` 自证一次。

## 镜像构建

- Docker Hub 与 PyPI 在本机直连不通，基础镜像走 DaoCloud 加速（`docker.m.daocloud.io/library/...`），Python 依赖走腾讯 PyPI 镜像，Maven 用 `services/api/maven-settings.xml` 指国内仓库。有梯子或云端构建时用 `:official` 变体切回官方源。
- 云托管只跑 `linux/amd64`，构建必须带 `--platform`。
- 静态站（介绍站）的绝对链接是**构建期**烘进产物的：sitemap、RSS、OG、canonical 全取自 `src/config.yaml` 的域名，所以 `SITE_URL` 是构建参数而不是运行时环境变量；换域名要重新构建。容器内没有站点内容可以改写。
- 不要把 profile 文件（`application-local.yaml` 之类）烘进镜像再强制激活 local profile，云上会起不来；密钥一律从云托管「环境设置-密钥」注入。

## 运行时约定

- 监听端口和健康检查路径要和 Dockerfile、控制台三处一致；介绍站走 nginx 监听 8080，健康检查 `/healthz`。
- api/chat/redis 之间走云托管内网地址，形态是 `ca-<env>.<服务名>.<仓库>.<域>.com:<端口>`（点号分隔、端口显式写），只在环境内可达。chat 调 api 用 `COOKING_API_BASE_URL`。
- LangGraph 的 checkpointer 需要 **redis-stack**（带 JSON 与 Search 模块）；纯 redis 会静默降级成 memory checkpointer，表现为"能跑但没有持久会话"。

## 小程序侧的域名规则

- 免域名/内网调用只对 HTTP 云调用生效，且必须走 `wx.cloud.callContainer`（带 `X-WX-SERVICE` 头）；`wx.request` 直连内网地址在真机不可达。
- WebSocket 不走云调用，必须公网 `wss://` 并配 socket 合法域名。
- 云托管默认公网域名 `*.sh.run.tcloudbase.com` 已备案，可直接填进合法域名；自有域名要先完成备案，再在云托管「自定义域名」绑定。
- api 服务需要配 request + uploadFile 两类合法域名，chat 服务需要配 socket 合法域名。
- 改生产域名后要更新 `apps/cooking-mini/.env.production` 并重新构建上传体验版。

## 平台常量

域名、环境 ID、镜像仓库名一律从控制台逐字复制。TCR 的 tag 删不掉（`docker manifest` 只有 create/inspect/push/rm/annotate，且 rm 不作用于远端），清理误推的 tag 只能进控制台操作。
