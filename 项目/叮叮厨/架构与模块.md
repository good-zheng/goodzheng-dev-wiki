# 叮叮厨 · 架构与模块

## 后端模块划分

`services/api` 是 Maven reactor 多模块，依赖方向单向：`api-bootstrap` → 业务模块 → `shared`。

| 模块 | 职责 |
| --- | --- |
| `shared` | 公共 DTO、`Result<T>` 响应包装、异常、对象存储抽象 |
| `identity` | 用户、认证、JWT、审批 |
| `recipe` | 菜谱、分类、TTS 合成 |
| `api-bootstrap` | 启动模块：`application.yaml`、`schema.sql`、DataInitializer、审计填充 |

对外路径前缀 `/api`（`server.servlet.context-path`，actuator 同前缀）。

## 持久层约定

- MyBatis-Plus 统一持久层：Mapper 是各模块 `repository` 包下继承 `BaseMapper<T>` 的 `@Mapper` 接口，只访问本模块的表。
- 实体用 `@TableName` / `@TableId(type = IdType.AUTO)`；创建时间 `@TableField(updateStrategy = FieldStrategy.NEVER)`，更新时间 `@TableField(fill = FieldFill.UPDATE)`，由 `api-bootstrap` 的 `AuditMetaObjectHandler` 填充。
- 表结构以 `api-bootstrap/src/main/resources/schema.sql` 为准（`spring.sql.init.mode: always` 幂等建表），不再由 JPA 自动建表；新表/新字段先改 schema.sql 再改实体。
- 全局 `update-strategy: always`（等价原 JPA merge 全字段）。
- 简单 CRUD 用 Wrapper；连表、resultMap、动态 SQL 走 XML mapper（放业务模块 `src/main/resources/mapper/XxxMapper.xml`，namespace 为接口全限定名，由 `mybatis-plus.mapper-locations` 加载）。示例：recipe 的 `selectDetailWithChildren` 用一次 LEFT JOIN 带出食材与步骤。
- 分页在 Controller/Service 层用 spring-data-commons 的 `Page`/`Pageable`，Service 内部用 `shared` 的 `MyBatisPages` 转换；依赖 `PaginationInnerInterceptor`。

## 认证与登录 gating

账号来源三类：微信 OpenID 一键登录（`Taro.login` 换 code）、用户名密码、App 注册。注册和 OpenID 新用户都进入审批流（`approval_status` = pending/approved/rejected），管理后台 `system/users/approval` 处理。小程序只认 `role === 'user'` 的会话。

界面 gating 的规则前后端一致，且踩过一次坑后固化：

- 游客可浏览：首页、分类、菜谱详情（后端 `GET /recipes*`、`/recipe-categories*` permitAll）、AI 聊天页的整个界面。
- 必须登录：开始做菜、聊天的**发送消息**动作（点发送才跳登录，输入前完全可见）、个人中心及子页、收藏/点赞/上传/UGC。
- 禁止自动强制跳转：被 gate 的 tab 页未登录时显示缺省页 + 「去登录」按钮，聊天页在输入栏上方挂登录提示条。自动重定向会导致返回时白屏。
- 跳登录前用 `po.auth.returnTo` 记录回跳地址。
- JWT 走 jjwt + `Authorization: Bearer`，401 统一触发前端 signOut。

## AI 聊天链路

- 入口是 `services/chat` 的 WebSocket `/ws/chat`（不带 `/api` 前缀），帧协议 `run_started / token / tool_call_result / error / done / pong`；`thread_id` 当作 conversation_id 贯穿会话。
- `po_agent_core`：Orchestrator + VerticalAgent（烹饪）+ CheckpointerManager + HybridRouter（dense embedding + BM25，alpha=0.3）。
- 模型：LLM 用 DeepSeek（OpenAI 兼容接口）；embedding 用阿里云百炼 MaaS 工作空间的 `qwen3.7-text-embedding`（dim 1024）。`AGENT_CORE_ROUTER_THRESHOLD` 必须显式设 0.55，默认 1.0 过严，实际相似度约 0.69 会全部落到兜底分支。
- 四层降级，设计目标是"坏掉也看起来正常"，所以排障要看日志不能只看行为：LLM 不可用 → EchoChatModel；Redis 不可用 → memory checkpointer；embedding 不可用 → 关键词路由；网络不可用 → OfflineCookingModel。
- 小程序 WS 客户端每消息新建连接，8s 连接超时 / 90s 运行超时 / 30s ping，失败静默回退本地规则回答。要验证真实连通看开发者工具 Network 的 socket 面板；URL 必须是 `ws://`/`wss://` 前缀，写成 `http://` 会静默失败。
- 生命周期用类式 `AppLifespan`（`__aenter__/__aexit__`），不用 `@asynccontextmanager`：后者在装配阶段抛异常时，关闭报错的堆栈会掩盖启动失败的真实原因。
- 陷阱：langchain 的 `OpenAIEmbeddings` 会预分词，阿里端点拒收，路由侧必须用 `semantic_router.OpenAIEncoder`。

## TTS 与对象存储

- 讯飞 TTS v2 走 WebSocket 合成，实现在 Java 侧 recipe 模块的 `tts/` 包；接口只返回**音频 URL**，不返回字节流。
- 音频落腾讯云 COS，键规则 `tts/recipes/{id}/{vcn}/...`，桶公共读，返回绝对公网 URL。
- 缓存优先：`POST /tts/prefetch` 批量预热，命中直接回 URL、未命中后台合成；小程序进详情页/做菜页即预取全部步骤音频与完成播报。
- COS 同时承载头像、封面、食材图上传（`/files/upload` 需登录，`/files/**` 的 GET 公开）。
- 完成提示音 `step-done.wav` 由后端静态目录 `/api/sounds/` 提供，两端共用一份。
