# 代码审查清单

适用范围：通用（规范示例偏后端，前端规范待补充）。

## 工作流程

1. 确定审查范围：用户指定的文件、diff 或 PR
2. 逐项过一遍下方清单
3. 按"反馈格式"输出结论，标注严重级别

## 审查清单

### 正确性
- [ ] 逻辑正确，覆盖边界条件（空值、越界、并发）
- [ ] 错误处理完整，异常路径有合理行为

### 安全性
- [ ] 无注入风险（SQL 注入、XSS、命令注入）
- [ ] 敏感信息（密钥、密码、token）未硬编码、未打日志

### 可维护性
- [ ] 命名表意清晰，函数职责单一
- [ ] 无重复代码；魔法数字已提取为常量
- [ ] 遵循项目既有代码风格与目录约定

### 测试
- [ ] 变更涉及的路径有对应测试
- [ ] 测试断言有效，不是"永真"断言

## 反馈格式

按严重级别分组输出：

- **Critical**：必须修复后才能合并（正确性缺陷、安全漏洞）
- **Suggestion**：建议改进（命名、结构、性能）
- **Nice to have**：可选优化

每条反馈附上文件与行号定位，Critical 项需说明触发条件与影响。
