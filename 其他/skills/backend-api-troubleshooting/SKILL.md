# 后端接口异常排查

适用范围：后端（HTTP API 服务）。先走通用排查六步法（见 [error-troubleshooting](../error-troubleshooting/SKILL.md)），本 Skill 提供接口场景的分流定位。

## 第一步：按现象分流

```text
接口异常现象
├── 5xx 响应            → 走「服务端错误」
├── 4xx 响应            → 走「客户端错误」
├── 响应慢 / 超时        → 走「性能劣化」
└── 200 但返回数据不对  → 走「数据错误」
```

## 服务端错误（5xx）

1. 用 traceId（或时间点 + 路由）在服务日志中检索完整堆栈
2. 堆栈定位到代码行后确认：空指针、越界、未捕获异常、依赖服务抛错
3. 区分偶发与必现：必现看代码路径；偶发看并发、超时、重试风暴与连接池耗尽

## 客户端错误（4xx）

1. 401/403：token 是否过期、权限配置是否包含该用户
2. 404：路由是否注册、网关是否转发、请求地址是否指向正确环境
3. 400/422：对照接口文档核对必填字段与类型；校验失败信息应指明具体字段

## 性能劣化（慢 / 超时）

1. 拆解耗时三段：网关耗时 / 应用处理 / 下游调用（DB、RPC、缓存）
2. DB 段慢：慢查询日志、缺索引、大事务、N+1 查询
3. 应用段慢：锁竞争、同步调用外部接口、大对象序列化
4. 与正常时期基线对比（发布记录、数据量变化），一次只验证一个变量

## 数据错误（200 但内容不对）

1. 固定一个具体 case：输入、期望输出、实际输出三方对照
2. 沿调用链核对：入参解析 → 业务分支 → 查询条件 → 字段映射，逐环打印中间值
3. 检查缓存一致性：脏缓存、序列化版本不一致、旧实例未失效

## 输出

排查结论沿用通用流程的汇报格式（根因 / 证据 / 修复 / 遗留风险）。
